## Temuan HIGH

### AS-001 [HIGH] Destination resources dan preferences tidak memiliki halaman yang benar

Status: static verified.

`AppShell` menampilkan `/docs/usage`, `/docs/contracts`, dan `/preferences`. `dev-main.tsx` menganggap semua pathname selain `/` sebagai docs page. `ComponentDocsPage` memakai `getComponentDoc(path) ?? componentRegistry[0]`, sehingga pathname yang tidak ada di registry jatuh ke halaman Button.

Akibatnya:

- `/docs/usage` merender halaman Button, bukan usage guide.
- `/docs/contracts` merender halaman Button, bukan contracts.
- `/preferences` dapat membuka panel sekaligus merender fallback Button docs.
- URL terlihat valid, tetapi content destination tidak sesuai.

Rule: R-24, R-26, C-2, C-4.

### AS-002 [HIGH] Tombol `Reset filter` adalah dead control

Status: static verified.

Di `src/components/showcase/ComponentShowcase.tsx`, tombol pada empty state dirender sebagai `<Button size="sm">Reset filter</Button>` tanpa `onClick`, `type`, atau state reset.

Akibatnya user mendapat janji aksi yang tidak terjadi.

Rule: R-26, C-2.

### AS-003 [HIGH] Beberapa kontrol interaktif tidak keyboard-operable

Status: static verified.

- `Popover` memakai `span onClick` sebagai trigger, tanpa elemen button atau keyboard handler.
- `DropdownMenu` memakai `span onClick` sebagai trigger.
- `Tooltip` memakai wrapper `span` untuk focus/hover, tetapi tidak memberi semantics trigger yang konsisten.
- `EventCalendar` merender event sebagai `<span role="button" tabIndex={0}>` tanpa `onKeyDown` untuk Enter/Space.
- `DataTable` memberi `tabIndex=0` pada row yang clickable, tetapi tidak memberi `onKeyDown` untuk Enter/Space.

Rule: R-32, R-26, C-4.

### AS-004 [HIGH] Interactive element bersarang di dalam button pada EventCalendar

Status: static verified.

`EventCalendar` merender setiap hari sebagai `<button>`, lalu merender event di dalamnya sebagai `<span role="button">`. Ini membuat interactive element berada di dalam interactive element dan memperumit focus order, screen reader announcement, dan activation behavior.

Rule: R-32, C-4.

### AS-005 [HIGH] Banyak tap target mobile di bawah 44px

Status: static verified.

CSS menetapkan beberapa kontrol di bawah ukuran minimum yang diminta R-03:

- `.edjavu-icon-button`: 34px.
- `.edjavu-brand-mark`: 34px.
- `.edjavu-avatar`: 30px.
- `.edjavu-nav-item`: minimum 40px.
- `.edjavu-preference-option`: padding yang menghasilkan tinggi sekitar 36px.
- `.docs-copy-button`: 30px.

Sebagian kontrol icon-only dan navigation dipakai langsung pada mobile. Belum ada browser measurement untuk semua breakpoint, tetapi source evidence cukup untuk menandai risiko HIGH.

Rule: R-03, R-32.

## Temuan MEDIUM

### AS-006 [MEDIUM] Core catalog belum sama dengan runtime export catalog

Status: static verified.

Dashboard menampilkan 29 documented pages, sedangkan `src/exposes/core.ts` dan expose lain memiliki lebih banyak symbol, termasuk subcomponent compound dan beberapa component yang belum punya halaman docs. README dan registry sudah menjelaskan perbedaan ini, tetapi UI tetap mudah dibaca sebagai catalog lengkap.

Masalahnya bukan jumlah 29 itu sendiri. Masalahnya adalah label dan discovery belum menjawab dengan jelas:

- jumlah documented surfaces;
- jumlah runtime exports;
- compound exports yang berada di bawah parent;
- runtime exports yang belum punya documentation page.

Rule: R-17, R-24, R-38, C-5.

### AS-007 [MEDIUM] Placeholder preview diperlakukan sebagai preview component

Status: static verified.

`ComponentDocsPage` memakai fallback:

`Interactive preview for {name}. The example uses the public contract shown below.`

Untuk sebagian besar halaman, preview tersebut bukan component yang benar-benar dirender, melainkan placeholder text. Halaman masih memiliki API dan variations, sehingga user dapat mengira preview telah memvalidasi behavior komponen.

Rule: R-26, R-38, C-5.

### AS-008 [MEDIUM] Showcase memakai data demo yang tampak seperti data product

Status: static verified.

Showcase menampilkan:

- chart values `24, 42, 31, 56, 48`;
- event `Catalog review`;
- status `Documented` dan `Stable channel`;
- sample file and interaction surfaces.

README memang menyebut sample values, dan chart diberi description `Sample data for validating the chart contract`. Namun label sample belum konsisten pada seluruh surface. Jika screenshot dipisahkan dari README, angka tersebut dapat terbaca sebagai product metrics.

Rule: R-17, R-23, R-38.

### AS-009 [MEDIUM] Dua sistem styling legacy masih di-import bersama sistem utama

Status: static verified.

`src/styles/styles.css` mengimpor `./global.css`, yang mengimpor `tokens.css` dan berisi CSS legacy dengan hardcoded colors, radius, shell classes, dialog classes, table classes, dan badge classes. Sistem utama menggunakan Tailwind v4 semantic variables di `styles.css`.

Keduanya belum terlihat dipakai bersama secara merata, tetapi keberadaan dua vocabulary styling membuat ownership, theme behavior, dan visual consistency sulit diaudit. Ini meningkatkan risiko komponen lama tidak mengikuti dark mode dan token baru.

Rule: R-20, R-21, R-29, R-31, C-1, C-4.

### AS-010 [MEDIUM] Design Read dan dials antislop belum ditulis

Status: static verified.

Tidak ditemukan `DESIGN.md` atau deklarasi eksplisit `ENERGY / RHYTHM / MOTION`. README hanya menyebut token Edjavu dan referensi struktural `invoicegen`.

User memang telah memberi referensi layout dan identitas project, sehingga audit ini tidak menyimpulkan bahwa visual direction sama sekali tidak ada. Yang hilang adalah keputusan yang dapat diaudit: focal point, rhythm, motion, typography rationale, dan alasan penggunaan blur/shadow/card hierarchy.

Rule: R-31, R-37, Part 3 Design Read.
